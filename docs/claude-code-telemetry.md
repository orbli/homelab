# Claude Code usage telemetry → Grafana

Dashboard: https://grafana-lab.orbb.li/d/claude-code-usage (provisioned from
`kubernetes/manifests/observability/claude-code-dashboard.yaml`, generated by
`claude-code-dashboard.gen.py` next to it).

## Pipeline

```
claude (any box on the tailnet)
  └─ OTLP http/protobuf ─▶ alloy.observability:4318 (otelcol.receiver.otlp)
        ├─ metrics ─▶ otelcol.exporter.prometheus (no suffixes) ─▶ Prometheus remote_write
        └─ logs    ─▶ otelcol.exporter.loki ─▶ Loki  {job="claude-code"}
```

ClusterIP service names resolve from the tailnet, so no port-forward is needed.

## Client env (per machine, `~/.claude/settings.json` → `env`)

```json
{
  "CLAUDE_CODE_ENABLE_TELEMETRY": "1",
  "OTEL_METRICS_EXPORTER": "otlp",
  "OTEL_LOGS_EXPORTER": "otlp",
  "OTEL_EXPORTER_OTLP_PROTOCOL": "http/protobuf",
  "OTEL_EXPORTER_OTLP_ENDPOINT": "http://alloy.observability.svc.home-hk1-cluster.orbb.li:4318",
  "OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE": "cumulative",
  "OTEL_RESOURCE_ATTRIBUTES": "host.name=<short-hostname>"
}
```

`host.name` is what the dashboard's **Host** variable filters on. Applies to
sessions started after the file is saved.

### Why `cumulative` is mandatory (2026-10-29 outage)

Claude Code 2.x exports metrics with **delta** temporality by default. Alloy's
`otelcol.exporter.prometheus` cannot convert delta sums and silently drops them;
only the resource-derived `target_info` series gets through, so Prometheus
looks "connected" while every `claude_code_*` metric is missing. Logs are not
affected (that is why Loki had months of `api_request` events while the
dashboard was empty). `otelcol.processor.deltatocumulative` would fix it
server-side but is still *experimental* in Alloy 1.10 and would require
lowering `--stability.level` on the DaemonSet — not worth it for a one-line
client setting.

Quick wire check for any client (prints temporality per metric: 1 = delta,
2 = cumulative). Save the receiver as `recv.py`:

```python
import http.server, json
class H(http.server.BaseHTTPRequestHandler):
    def do_POST(s):
        b = s.rfile.read(int(s.headers['Content-Length']))
        if s.path.endswith('metrics'):
            for rm in json.loads(b)['resourceMetrics']:
                for sm in rm['scopeMetrics']:
                    for m in sm['metrics']:
                        print(m['name'], m.get('sum', {}).get('aggregationTemporality'), flush=True)
        s.send_response(200); s.end_headers(); s.wfile.write(b'{}')
    def log_message(*a): pass
http.server.HTTPServer(('127.0.0.1', 4319), H).serve_forever()
```

Then:

```sh
python3 recv.py &
cat > /tmp/otel-local.json <<'JSON'
{"env":{"CLAUDE_CODE_ENABLE_TELEMETRY":"1","OTEL_METRICS_EXPORTER":"otlp",
 "OTEL_EXPORTER_OTLP_PROTOCOL":"http/json","OTEL_EXPORTER_OTLP_ENDPOINT":"http://127.0.0.1:4319",
 "OTEL_METRIC_EXPORT_INTERVAL":"2000"}}
JSON
claude -p ok --model haiku --settings /tmp/otel-local.json
```

(`--settings` needs Claude Code 2.x; on the WSL box the real binary is
`~/.claude/local/node_modules/.bin/claude`, a stale 1.0.35 shadows it at
`/usr/local/bin/claude`.)

## Data shape (drives the dashboard queries)

* Metric names are bare: `claude_code_cost_usage`, `claude_code_token_usage{type}`,
  `claude_code_session_count`, `claude_code_active_time_total`,
  `claude_code_lines_of_code_count{type=added|removed}`, `claude_code_commit_count`,
  `claude_code_pull_request_count`.
* Labels: `host_name`, `model`, `effort`, `query_source`, `session_id`,
  `terminal_type`, plus user/org identity labels.
* Counters are cumulative **per session** (`session_id`): they start at the
  first turn's value and end when the process exits. `increase()` and `rate()`
  under-count that shape, so the dashboard uses

  ```
  (last_over_time(m[W]) - (last_over_time(m[W] offset W) and last_over_time(m[W]))) or last_over_time(m[W])
  ```

  which attributes each session's growth to the right bucket exactly.
* Loki lines are `{"body":"claude_code.<event>","attributes":{...}}`; `| json`
  exposes `attributes_duration_ms`, `attributes_model`, `attributes_tool_name`,
  `attributes_success`, `attributes_ttft_ms`, `attributes_cost_usd`, …
  Events seen: api_request, api_error, tool_decision, tool_result, user_prompt,
  assistant_response, mcp_server_connection, hook_execution_*, compaction, auth.
